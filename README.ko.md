# Func-Forger

> 언어: [English](README.md) · **한국어** · [中文](README.zh.md) · [日本語](README.ja.md) — 영문(English)이 기준 원본입니다.

> **핵심 아이디어.** Func-Forger는 모든 것을 LLM 에이전트에게 맡기는 방식을
> 넘어, LLM을 코딩 워크플로우 전체를 가속하는 데 활용하면서도 LLM에 가해지는
> *추론 부담은 줄*입니다. 그 결과 사람이 코드베이스 전체에 대한 주도권을 갖고,
> 더 저렴한 오픈소스나 저수준 모델로도 프로젝트를 효과적으로 진행할 수
> 있습니다. 특히 **로컬 모델만 사용할 수 있는 환경**에서 가장 큰 빛을 발합니다.

대부분의 AI 코딩 도구는 LLM에게 *무엇을* 만들지, *어떻게* 구조를 잡을지,
*어떻게* 구현할지까지 모두 떠넘깁니다. 이는 가장 강력한(그리고 비싼) 모델만이
잘 감당하는 무거운 추론 부담이며, 코드베이스의 형태를 조용히 모델에 넘겨주게
됩니다. Func-Forger는 이 역할 분담을 뒤바꿉니다:

- **설계는 사람이.** *스켈레톤*을 작성합니다 — 모든 최상위 정의(함수,
  구조체/클래스, typedef, 매크로 …)의 뼈대와 선택적 방향 주석을. 즉 *무엇을*
  만들지, 코드베이스를 *어떻게* 조직할지는 모델이 아닌 당신의 결정으로 남습니다.
- **LLM은 잘 정의된 본문만 채웁니다.** 아키텍처가 아닌 구현만. 이는 훨씬 작은
  추론 과제라서 더 약하거나 저렴한 모델로도 충분하며, 결과물은 사람이 검증하기에도
  단순합니다.
- **만들어진 코드는 바텀업으로 재사용.** 구현된 각 정의는 rustdoc 수준으로
  문서화되어 색인되고, 커지는 라이브러리에 정리됩니다. 새 정의는 그 라이브러리를
  검색해 기존 것들을 조합하며, 매번 다시 발명하지 않습니다.

결과적으로, LLM이 단순 반복을 가속하는 동안 코드베이스의 주도권은 당신에게
있습니다 — 로컬 오픈소스 모델만으로 충분하며, 클라우드 모델은 필요 없습니다.

> 철학: **사람은 바텀업으로 설계하고, LLM은 구현·문서화·구조화한다 — LLM은
> 구현만 하므로, 수준이 낮은 모델로도 충분하다.**

## 인터페이스 (TUI)

두 패널의 터미널 앱:

```
+-------------------------------+----------------+
|                               | search [____]  |
|         editor                | functions      |
|   skeleton  <-->  code        |   ...          |
|                               | files          |
|                               |   ...          |
+-------------------------------+----------------+
| status / hints                                  |
+------------------------------------------------+
```

- **왼쪽**: 스켈레톤(및 생성된 코드 검토/수정)용 코드 에디터. `F3`으로 현재 버퍼를
  `$EDITOR`(vim)에서 여는 진짜 모달 세션도 가능.
- **오른쪽 사이드**: 실시간 라이브러리 **검색**, **함수 목록**(항목 선택 시 소스
  조회), 언어·역할별로 묶인 **파일 트리**.

### 단축키

| 키 | 동작 |
|---|---|
| `Ctrl+G` | **Forge** — 에디터의 스켈레톤 구현 |
| `Ctrl+P` | **승인** — 생성 코드 저장 + 색인 + 사이드바 새로고침 |
| `Ctrl+N` | **거부** (스켈레톤 복원) |
| `Ctrl+E` | 생성 코드 **편집** 모드 토글 |
| `Ctrl+R` | 선택 범위만 **재생성** (범위 잠금, 설명 선택) |
| `Ctrl+K` | 새 스켈레톤을 위해 에디터 비우기 |
| `Ctrl+B` | 진행 중이던 스켈레톤으로 복귀 |
| `Ctrl+L` | 함수 목록으로 포커스 |
| `F2` | 대상 언어 설정 |
| `F3` | 버퍼를 `$EDITOR`(vim)로 열기 |
| `Ctrl+Q` | 종료 |

### Forge 흐름

1. 에디터에 스켈레톤을 작성한 뒤 `Ctrl+G`.
2. **에이전트**가 라이브러리를 검색(`SEARCH:` 도구 + 자동 시드)하고, 가능한 곳에서
   기존 함수를 조합합니다.
3. 각 함수 위에 **rustdoc 문서**(요약, Arguments, Returns, Behavior)를 작성합니다.
   이 문서는 색인되어 향후 검색을 구동합니다.
4. 생성 중에는 스피너가, 이후 스켈레톤→코드 애니메이션으로 코드가 표시됩니다.
5. **검토**: 승인/거부/직접 수정/선택 범위 재생성. 승인 시 파일이
   `library/<lang>/<category>/<module>.<ext>`에 저장되고, 색인되며 사이드바가
   새로고침됩니다.

## 검색과 재사용이 핵심입니다

모든 함수의 문서는 매니페스트로 추출되어 검색 대상이 됩니다. 토큰화는
식별자(`double_sum`, `parseCSV` → 단어)를 분리하고 일반 불용어를 제거하며, 점수는
**이름** > **설명** > **doc** 순으로 가중합니다. 그래서 `sum two integers` 같은
질의가 표면형이 전혀 다른 `add`를 찾아냅니다. 이것이 `double_sum`이 `add`를 자동으로
재사용하게 하는 메커니즘입니다.

## 언어 무관

생성 코드는 **어떤 언어**든 가능합니다. Func-Forger는 코드를 실행하지 않으므로
언어별 런타임 의존성이 없고, 그래야 진짜 언어 독립성이 가능해집니다.

## 하지 않는 것

Func-Forger는 **코드 생성과 저장만** 합니다. 컴파일/실행/테스트는 하지 않습니다.
스켈레톤이 잘 정의되어 있으면 결과 검증은 간단하며, 그 검증은 설계상 사람에게
맡겨집니다.

## 설정 가능한 LLM 백엔드

원하는 모델을 사용하세요. Func-Forger는 설정한 어떤 LLM API와도 대화합니다:

- **프라이버터리** — Anthropic Claude, OpenAI GPT, Google Gemini, …
- **오픈소스 / 자체 호스팅** — OpenAI 호환 엔드포인트(Ollama, vLLM, LM Studio,
  Together, Groq, …) 또는 Anthropic 호환 프록시.

provider, base URL, model, API key는 CLI 플래그, 환경변수, 인앱 명령으로 설정
가능합니다.

## 실행

```bash
pip install -e .            # anthropic, openai, textual 설치
forger                      # TUI (기본)
forger --repl               # 구형 대화형 REPL
forger --provider openai-compat --base-url http://localhost:11434/v1 --model llama3.1
```

자격증명은 일반적인 환경변수에서 읽습니다(`ANTHROPIC_API_KEY` /
`ANTHROPIC_AUTH_TOKEN` / `OPENAI_API_KEY`, 선택 `*_BASE_URL`).
