# Func-Forger

> 言語：[English](README.md) · [한국어](README.ko.md) · [中文](README.zh.md) · **日本語** — 英語が正（canonical）のバージョンです。

> **核となるアイデア。** Func-Forger は、すべてを LLM エージェントに任せるやり方を
> 超えます。LLM をコーディングのワークフロー全体を加速するために使いながら、
> モデルにかかる*推論の負担は減らし*ます。その結果、人間がコードベース全体に対する
> 主導権を保ち、より安価なオープンソースや低水準のモデルでもプロジェクトを効果的に
> 進められます。特に**ローカルモデルしか使えない環境**で最大の威力を発揮します。

ほとんどの AI コーディングツールは、LLM に*何を*作るか、*どう*構成するか、
*どう*実装するかまで全て押し付けます。これは最も強力な（そして高価な）モデルで
ないとうまくこなせない重い推論負担であり、コードベースの形を静かにモデルに
明け渡すことになります。Func-Forger はこの分業を逆転させます：

- **設計は人間が握る。** *スケルトン*を書きます — すべてのトップレベル定義（関数、
  構造体/クラス、typedef、マクロ……）の骨組みと、任意の方向コメントを。つまり
  *何を*作るか、コードベースを*どう*構成するかは、モデルではなくあなたの決定の
  ままです。
- **LLM は定義が明確な本体だけを埋める。** アーキテクチャではなく実装のみ。これは
  はるかに小さな推論課題なので、より弱い/安価なモデルでも十分であり、出力は人間が
  検証するにもシンプルです。
- **作ったものはボトムアップで再利用される。** 実装された各定義は（rustdoc 級に）
  ドキュメント化され、索引付けされ、成長するライブラリに整理されます。新しい定義は
  そのライブラリを検索して既存のものを組み合わせ、毎回作り直しません。

結果として、LLM が単純作業を加速する間、コードベースの主導権はあなたにあります —
ローカルのオープンソースモデルだけで十分で、クラウドモデルは不要です。

> 理念：**人間がボトムアップで設計し、LLM が実装・ドキュメント化・構造化する —
> LLM は実装だけなので、並程度のモデルでも十分です。**

## インターフェース（TUI）

2ペインのターミナルアプリ：

```
+-------------------------------+----------------+
|                               | search [____]  |
|         editor                | functions      |
|   skeleton  <-->  code        |   ...          |
|                               | files          |
|                               |   ...          |
+-------------------------------+----------------+
| status / hints                                  |
+------------------------------------------------+
```

- **左側**：スケルトン（および生成コードのレビュー/編集）用のコードエディタ。
  `F3` で現在のバッファを `$EDITOR`（vim）で開き、本物のモーダルセッションを
  使えます。
- **右サイドバー**：リアルタイムのライブラリ**検索**、**関数リスト**（項目を選ぶと
  ソースを表示）、言語・役割別にまとめられた**ファイルツリー**。

### キーバインド

| キー | 動作 |
|---|---|
| `Ctrl+G` | **Forge** — エディタのスケルトンを実装 |
| `Ctrl+P` | 生成コードを**承認**（保存 + 索引 + サイドバー更新） |
| `Ctrl+N` | **却下**（スケルトンを復元） |
| `Ctrl+E` | 生成コードの**編集**モード切替 |
| `Ctrl+R` | 選択範囲だけ**再生成**（範囲固定、説明は任意） |
| `Ctrl+K` | 新しいスケルトン用にエディタをクリア |
| `Ctrl+B` | 作業中のスケルトンに戻る |
| `Ctrl+L` | 関数リストにフォーカス |
| `F2` | 対象言語の設定 |
| `F3` | バッファを `$EDITOR`（vim）で開く |
| `Ctrl+Q` | 終了 |

### Forge の流れ

1. エディタにスケルトンを書き、`Ctrl+G`。
2. **エージェント**がライブラリを検索（`SEARCH:` ツール + 自動シード）し、可能な
   ところで既存関数を組み合わせます。
3. 各関数の上に **rustdoc 風ドキュメント**（要約、引数、戻り値、振る舞い）を書きます。
   このドキュメントは索引付けされ、以降の検索を支えます。
4. 生成中はスピナー、その後スケルトン→コードのアニメーションでコードが表示されます。
5. **レビュー**：承認/却下/手動編集/選択範囲の再生成。承認すると
   `library/<lang>/<category>/<module>.<ext>` に保存され、索引付けされ、サイドバーが
   更新されます。

## 検索と再利用がポイント

すべての関数のドキュメントはマニフェストに抽出され、検索対象になります。トークン化は
識別子（`double_sum`、`parseCSV` → 単語）を分割し一般的なストップワードを取り除き、
スコアは**名前** > **説明** > **doc** の順に重み付けします。だから `sum two integers`
のような問い合わせが、表面形が全く異なる `add` を見つけます。これが `double_sum` が
`add` を自動再利用する仕組みです。

## 言語非依存

生成コードは**任意の言語**で書けます。Func-Forger はコードを実行しないので、言語別の
ランタイム依存がなく、それが真の言語独立性を可能にします。

## やらないこと

Func-Forger は**コードの生成と保存のみ**を行います。コンパイル/実行/テストは一切
しません。スケルトンが整っていれば出力の検証は容易で、その検証は設計上人間に
委ねられます。

## 設定可能な LLM バックエンド

好きなモデルを使えます。Func-Forger は設定した任意の LLM API と対話します：

- **プロプライエタリ** — Anthropic Claude、OpenAI GPT、Google Gemini……
- **オープンソース / セルフホスト** — OpenAI 互換エンドポイント（Ollama、vLLM、
  LM Studio、Together、Groq……）または Anthropic 互換プロキシ。

プロバイダ、ベース URL、モデル、API key は CLI フラグ、環境変数、アプリ内コマンドで
設定できます。

## 実行

```bash
pip install -e .            # anthropic、openai、textual をインストール
forger                      # TUI（デフォルト）
forger --repl               # 旧版の対話式 REPL
forger --provider openai-compat --base-url http://localhost:11434/v1 --model llama3.1
```

資格情報は一般的な環境変数から読みます（`ANTHROPIC_API_KEY` /
`ANTHROPIC_AUTH_TOKEN` / `OPENAI_API_KEY`、任意 `*_BASE_URL`）。
