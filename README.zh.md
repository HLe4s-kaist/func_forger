# Func-Forger

> 语言：[English](README.md) · [한국어](README.ko.md) · **中文** · [日本語](README.ja.md) —— 英文为权威版本。

> **核心理念。** Func-Forger 不再把一切都交给 LLM 代理。它用 LLM 加速整个
> 编码工作流，同时*降低*施加在模型上的推理负担——这样人类始终掌握整个代码库的
> 主导权，更廉价的开源或较低档次的模型也能有效地推进项目。它在**只能使用本地
> 模型**的环境中尤为出色。

大多数 AI 编码工具让 LLM 负责*做什么*、*如何组织*以及*如何实现*——这是一种沉重
的推理负担，只有最强大（也最昂贵）的模型才能胜任，并悄悄地把代码库的形态交给了
模型。Func-Forger 颠覆了这种分工：

- **设计由人类掌握。** 你编写*骨架*——每个顶层定义（函数、结构体/类、typedef、
  宏……）的骨架加上可选的方向注释——因此*做什么*和代码库*如何组织*始终是你的
  决定，而不是模型的。
- **LLM 只填充定义明确的函数体。** 只做实现，不做架构。这是一个小得多的推理任务，
  更弱或更便宜的模型就足够了——而且产出对人而言也更易于验证。
- **已完成的工作自底向上复用。** 每个已实现的定义都被（rustdoc 级别地）文档化、
  建立索引，并归档到一个不断增长的库中；新的定义会搜索该库并组合已有定义，而不是
  重新发明。

净效果是：LLM 加速繁琐工作的同时，你始终掌控代码库——本地开源模型就够了，不需要
云端模型。

> 理念：**人类自底向上设计；LLM 负责实现、文档化与结构化——而因为 LLM 只负责
> 实现，即便普通模型也够用。**

## 界面（TUI）

双栏终端应用：

```
+-------------------------------+----------------+
|                               | search [____]  |
|         editor                | functions      |
|   skeleton  <-->  code        |   ...          |
|                               | files          |
|                               |   ...          |
+-------------------------------+----------------+
| status / hints                                  |
+------------------------------------------------+
```

- **左侧**：用于编写骨架（以及审阅/编辑生成代码）的代码编辑器。按 `F3` 可在
  `$EDITOR`（vim）中打开当前缓冲区，获得真正的模态编辑体验。
- **右侧栏**：实时库**搜索**、**函数列表**（选择条目以查看其源码），以及按语言
  和角色分组的**文件树**。

### 快捷键

| 键 | 动作 |
|---|---|
| `Ctrl+G` | **Forge** — 实现编辑器中的骨架 |
| `Ctrl+P` | **通过**生成代码（保存 + 索引 + 刷新侧栏） |
| `Ctrl+N` | **拒绝**（恢复骨架） |
| `Ctrl+E` | 切换生成代码的**编辑**模式 |
| `Ctrl+R` | 仅**重新生成**所选范围（范围锁定；说明可选） |
| `Ctrl+K` | 清空编辑器以编写新骨架 |
| `Ctrl+B` | 回到进行中的骨架 |
| `Ctrl+L` | 聚焦函数列表 |
| `F2` | 设置目标语言 |
| `F3` | 在 `$EDITOR`（vim）中打开缓冲区 |
| `Ctrl+Q` | 退出 |

### Forge 流程

1. 在编辑器中编写骨架，然后按 `Ctrl+G`。
2. **代理**搜索库（显式的 `SEARCH:` 工具**加上**自动注入的候选项），并尽可能把
   已有函数组合进新函数。
3. 它在每个函数上方编写 **rustdoc 风格的文档**（摘要、参数、返回、行为）。该文档
   被索引并驱动后续搜索。
4. 生成期间显示转圈动画，随后以“骨架→代码”动画呈现代码。
5. **审阅**：通过、拒绝、手改或重新生成所选范围。通过后文件写入
   `library/<lang>/<category>/<module>.<ext>`，建立索引并刷新侧栏。

## 搜索与复用是关键

每个函数的文档都会被提取到清单中作为搜索对象。分词会把标识符拆开
（`double_sum`、`parseCSV` → 单词）并去掉常见停用词，打分对**名称**的权重大于
**描述**，又大于**文档**，因此 `sum two integers` 这样的查询能找到表面形式完全
不同的 `add`。这正是让 `double_sum` 自动复用 `add` 的机制。

## 语言无关

生成的代码可以是**任何语言**。由于 Func-Forger 从不执行代码，它没有针对语言的
运行时依赖——这正是真正语言独立性得以可能的原因。

## 它*不*做的事

Func-Forger **只生成和存储代码**。它不编译、不运行、不测试任何东西。只要骨架是
规范的，验证产出就很直接——而该验证在设计上交由人类完成。

## 可配置的 LLM 后端

自带模型。Func-Forger 能与你配置的任何 LLM API 对话：

- **商业** —— Anthropic Claude、OpenAI GPT、Google Gemini……
- **开源 / 自托管** —— 任何 OpenAI 兼容端点（Ollama、vLLM、LM Studio、Together、
  Groq……）或 Anthropic 兼容代理。

提供商、base URL、模型和 API key 可通过 CLI 参数、环境变量或应用内命令配置。

## 运行

```bash
pip install -e .            # 安装 anthropic、openai、textual
forger                      # TUI（默认）
forger --repl               # 旧版对话式 REPL
forger --provider openai-compat --base-url http://localhost:11434/v1 --model llama3.1
```

凭据从常用环境变量读取（`ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` /
`OPENAI_API_KEY`，可选 `*_BASE_URL`）。
